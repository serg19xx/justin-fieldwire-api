# Сводка по интеграции системы логирования

## ✅ Вы правы! Бэкенд интеграция - правильное решение

### 🎯 **Почему вызовы из бэкенда лучше:**

1. **Надежность** - гарантированное выполнение при изменении данных
2. **Безопасность** - API ключи и секреты остаются на сервере  
3. **Простота** - один вызов в нужном месте кода
4. **Контроль** - полный контроль над условиями отправки
5. **Контекст** - автоматическое определение контекста операции

### ❌ **Проблемы фронтенд интеграции:**
- Пользователь может закрыть браузер
- API ключи видны в коде
- Дублирование логики
- Сложность передачи контекста

### 3. **API эндпоинты для управления событиями**

- `PUT /api/v1/event-logs/outbox/{id}/status` - обновление статуса outbox события

## 🔧 **Как интегрировать в существующий код**

### Простой пример:

```php
// В вашем контроллере
private EventLoggingService $eventLoggingService;

public function __construct(Logger $logger)
{
    $this->eventLoggingService = new EventLoggingService($logger);
}

// В методе обновления
public function updateTaskStatus(int $taskId, string $newStatus): void
{
    // 1. Получаем текущие данные
    $currentTask = $this->getTaskById($taskId);
    
    // 2. Обновляем в БД
    $this->updateTaskInDatabase($taskId, ['status' => $newStatus]);
    
    // 3. Логируем событие (автоматически создаст outbox события)
    $this->eventLoggingService->logEvent(
        entityType: 'task',
        entityId: $taskId,
        eventType: 'STATUS_CHANGED',
        beforeData: ['status' => $currentTask['status']],
        afterData: ['status' => $newStatus],
        changedFields: ['status', 'updated_at'],
        options: [
            'comment' => "Task status changed from {$currentTask['status']} to {$newStatus}",
            'actor_type' => 'user',
            'actor_id' => $this->getCurrentUserId()
        ]
    );
}
```

## 🎯 **Сценарии использования**

### Сценарий 1: Ручной триггер
1. Пользователь нажимает кнопку "Завершить задачу"
2. Бэкенд обновляет статус и логирует событие
3. N8N получает outbox событие и отправляет уведомления
4. Менеджер получает уведомление в Slack/Email

### Сценарий 2: Автоматизированный отчет
1. N8N запускается по расписанию (каждый день в 9:00)
2. Вызывает API для сбора данных за вчерашний день
3. Обрабатывает данные и форматирует отчет
4. Отправляет отчет руководителям разных уровней
